# Repo Guard v0.2.0

**Repo Guard is a Git and Git LFS file-safety policy engine** — not a hook manager. v0.2.0 adds hook-manager coexistence, outgoing push/history validation, and CI-friendly enforcement while keeping v0.1 staged-index safety.

This is an **early public release**. Pin versions, run `repo-guard doctor`, and read [docs/compatibility-matrix.md](../compatibility-matrix.md) before production rollout.

## Highlights

### Staged-index validation (v0.1 baseline, refined)

- `repo-guard check` inspects the **Git index**, not just the working tree
- Threshold-based LFS vs regular blob policy
- Exact `git lfs track --filename` repair commands
- Text and JSON output with stable exit codes

### Hook-manager interoperability (v0.2)

- `repo-guard detect` — read-only detection of pre-commit, Husky, Lefthook, custom `core.hooksPath`, and native hooks
- Standalone `.githooks` mode only when no competing owner is detected
- `integrate * --print` — reviewable snippets; **no automatic** external config edits
- Root pre-commit manifest with hook id **`repo-guard-check`**

### Outgoing push and history validation

- `repo-guard hook pre-push` — validates outgoing objects from Git's stdin ref list
- Preserves stdin for `git lfs pre-push`
- `repo-guard history check --range` and `--all`
- **`--advisory`** — unresolved remote baselines become warnings instead of errors; **outgoing blob policy violations still fail** (strict by default without `--advisory`)
- Skips ref deletions; deduplicates blobs across multiple pushed refs

### CI support

- Reference workflow: `.github/workflows/repo-guard-ci.yml`
- Matrix: Ubuntu, Windows, macOS
- `cargo audit` on every quality job
- Policy example job: PR range `history check`

## Installation

Source install with Cargo (no crates.io package in this release):

```bash
git clone https://github.com/kd3f/repo-guard.git
cd repo-guard
cargo install --path . --locked
```

Requires Rust **1.92.0** per `rust-toolchain.toml`, plus Git and Git LFS.

## Known limitations

- **No external-manager pre-push integration** — Husky/Lefthook/pre-commit cannot delegate push validation to Repo Guard in v0.2.0
- **No automatic LFS migration** or history rewrite
- **No pre-built binaries** or crates.io publish in this release line
- **Local hooks can be bypassed** — use CI `history check` for team enforcement
- **`--advisory`** relaxes only unresolved-baseline handling; large regular blobs still block

## Upgrade from v0.1

- Run `repo-guard detect` before `init --apply` / `install --apply` on existing repos
- Add CI `history check` if you relied only on local hooks for push safety
- pre-commit consumers: use hook id `repo-guard-check` and run Repo Guard **after** index-mutating hooks
